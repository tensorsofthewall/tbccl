# TBCCL 0.7.1 validation

```{warning}
**This is not a certification.** TBCCL 0.7.1 is a security-maintenance patch release of 0.7.0 (C ABI 1, wire protocol 4, endpoint blob format 1). Nothing under `src/` or `include/` changed, so the runtime and physical evidence of 0.7.0 stands and is not repeated; this page records what is specific to 0.7.1.
```

## What changed

The build environment and the documentation tooling after the October 2026 emSign CA removal: certifi 2026.10.19 for the documentation build, pip 26.2.2 from its hash-pinned wheel and uv 0.13.5 in the CI jobs, a patched manylinux_2_28 image digest (the compilers are unchanged), the revoked emSign root blocked in the build container, and a policy check. See the changelog and `SECURITY.md`. This is not a vulnerability fix: none of the 0.7.0 archives contains a CA bundle or performs TLS.

## Why no physical requalification

The maintenance policy treats a CI, documentation or release-metadata change as needing no physical Thunderbolt run. The library sources are identical to 0.7.0 (`git diff v0.7.0 v0.7.1 -- src include` is empty), the C ABI and wire protocol are unchanged, and the artifact build is the same recipe in a different container image. The 0.7.1 archives are compared with the 0.7.0 archives member by member in the maintainers' release record; the native test suite runs on Linux and macOS in the release workflow.

## Release artifacts

The CI-built archives, checksums, SBOMs and attestations are verified from the outside with `tools/verify_public_release.py --download` after publication; the result is recorded in the release notes of the GitHub release.
